# PRD — arc-webui (2-panel HITL+AFK rewrite)

**Status:** ready-for-agent
**Owner:** interviewer (S0), developer (S1–S8), admin (S9–S10)
**Supersedes:** ~/projects/webui/ (chat, encounters, map, kanban surfaces)
**Issue tracker:** ledger.db (`kind=prd`, this file referenced by `artifact_dir`)

---

## Problem Statement

The current arc-webui at `~/projects/webui/` exposes four separate surfaces (chat, encounters, map, kanban) which are visually unsatisfying, feature-bloated, and not mobile-first. The user runs autonomous agents 24/7 from a phone over Tailscale; the current UI demands a laptop and rewards exhaustive browsing rather than focused triage. The HITL loop is slow (replies must be composed from scratch every time) and the AFK observation surface is fragmented across views that show the same ledger data three different ways without giving the user a "what should I look at right now" answer.

## Solution

Replace the four-surface webui with a two-panel mobile-first interface served over Tailscale.

**HITL panel** is a single-thread-at-a-time triage surface. The interviewer agent pre-drafts the top-3 highest-priority `chat_in` / `encounter_reply` threads with full context, a recommended reply, 2–3 alternatives, and rendered artifacts. The user pans through threads, edits or accepts a draft, and submits. New chat_in arrivals shuffle the rank and trigger regeneration of displaced drafts.

**AFK panel** is a tech-tree DAG of ledger state, scoped to (last-10 completed) + in-flight + hitl_blocked + pending. Nodes show a 10-word status on hover; tap opens the thread in HITL with artifacts (commits, screenshots, prototypes, charts, video clips), allowing the user to discuss blockage or plan followup tasks. Pause and defer buttons set ledger state directly. Layout positions in-flight center, completed left, pending right, minimizing connector crossings.

Pre-drafts are cached on the ledger row so panning between threads is instant. Real-time updates flow via SSE bound to the Tailscale interface only. The two new panels replace four old surfaces; once stable, the old surfaces are moved to trash.

## User Stories

### HITL panel
1. As a mobile user on Tailscale, I want the top-priority chat thread to load instantly with a pre-drafted reply, so that I can triage agent questions in seconds rather than minutes.
2. As a single-user operator, I want to see 2–3 alternative replies generated by the interviewer, so that I can pick the framing I like without composing from scratch.
3. As a user, I want a custom-reply textbox below the alternatives, so that I can override or amend the draft when needed.
4. As a user panning between threads, I want focus on a non-top-1 thread to trigger draft generation, so that I can review lower-priority threads without permanent pre-drafting costs.
5. As a user, I want generated drafts cached on the ledger row, so that returning to a thread within minutes does not waste compute.
6. As a user, I want each thread to show full context (parent task, artifacts, agent reasoning), so that I don't need to remember why this question was raised.
7. As a user, I want chat_in arrivals that bump rank into top-3 to trigger regeneration of displaced drafts, so that what I see is always the freshest version.
8. As a user, I want submitting a reply to write a `chat_out` row to the ledger, so that the interviewer can act on my response within its next loop.
9. As a user, I want the HITL panel readable on a 375px-wide phone screen, so that I can triage from anywhere.

### AFK panel
10. As a user observing autonomous work, I want a DAG view scoped to "last-10 completed + all in-flight + all pending/blocked", so that the visible graph stays under ~50 nodes and remains readable on mobile.
11. As a user, I want in-flight tasks rendered in the center of the DAG, with completed left and pending right, so that the "what is happening right now" answer is immediately visible.
12. As a user, I want the DAG layout to minimize connector crossings (Sugiyama-style layered layout), so that the dependency structure is legible.
13. As a user, I want hover on a node to show a 10-word status update, so that I can scan the graph without opening every thread.
14. As a user, I want tap-on-node to open that task's thread in the HITL panel with its artifacts, commits, and discussion, so that observation flows directly into intervention.
15. As a user, I want artifact galleries (charts, screenshots, prototypes, video clips, A/B variants) attached to in-flight, hitl_blocked, and completed tasks, so that I can judge agent work without reading raw commits.
16. As a user tapping a pending task, I want a discussion surface for prioritize/cancel/split decisions, so that backlog grooming is one tap from the DAG.
17. As a user tapping an in-flight task with no artifacts yet, I want a "no output yet" placeholder, so that I am not confused by an empty gallery.
18. As a user, I want pan and zoom on the DAG, so that I can navigate ~50 nodes on a phone screen.
19. As a user, I want a "pause" button on each node, so that I can prevent the task from starting without losing its place in the queue.
20. As a user, I want a "defer" button on each node, so that I can drop a task to the back of the unblocked queue while higher-priority work proceeds.
21. As a user, I want artifact galleries with >10 files to lazy-load, so that opening a completed task does not stall on mobile.
22. As a user, I want the DAG home position to recompute when topology changes (new row, state transition), but be cached otherwise, so that the view feels stable.

### Pause / defer / priority
23. As a user, I want pausing a task to set `state=paused` and hide it from the DAG, so that paused work doesn't clutter the live view.
24. As a user, I want deferring a task to drop its priority by 100 (rejoin queue at `priority - 100`), so that defer is reversible-by-time as new tasks arrive at normal priority.
25. As a user, I want the waiter to skip paused and deferred rows when scanning for claimable work, so that pause/defer actually prevents agent pickup.
26. As a user, I want unpause/un-defer to be possible from the same node menu, so that I can change my mind.

### Sync, auth, infra
27. As a user, I want server-sent events (SSE) pushing ledger deltas to both panels, so that state changes appear without manual refresh.
28. As a user, I want SSE to reconnect with `Last-Event-ID` on drop, so that mobile network blips don't desync the UI.
29. As a single-user operator, I want the webui server to bind to the tailscale0 interface only, so that the control surface is never publicly reachable.
30. As a user, I want the server to hard-fail at boot if the tailscale interface is missing, so that misconfiguration never falls back to 0.0.0.0.
31. As a user, I want no public auth tokens or path-secret URLs, so that the only auth surface is Tailscale ACL.

### Trash old surfaces
32. As a user, I want the old chat/encounters/map/kanban routes moved to `~/trash/<unix-ts>_arc-webui-old-YYYYMMDD/` after v1 ships and soaks for 7 days, so that the new panels are not competing with stale surfaces.
33. As a user, I want a verification step that no live director-cycle output links to the old surfaces, so that nothing breaks after removal.

### Visual style
34. As a user, I want the UI rendered with quality charts, diagrams, and graphs (not generic web defaults), so that the AFK panel feels like a tech tree, not a TODO list.
35. As a user, I want a /claude-design pass producing tokens, components, and motion spec from a paper sketch, so that visual style is intentional rather than emergent.
36. As a user, I want the reference image dossier (6 game tech trees + 4 productivity tools) reviewed by me before any UI code is written, so that the visual target is narrowed to 2–3 concrete inspirations.
37. As a user, I want sound and animation treated as nice-to-have, not blocking v1, so that schedule risk does not bloat the MVP.

## Implementation Decisions

### Architecture
- **Two panels only:** HITL and AFK. No "map," no "kanban," no separate "chat" or "encounters." Old surfaces removed in S9.
- **Mobile-first:** 375px design target, 1024px secondary. Tap targets ≥44pt.
- **Stack pick deferred to S0:** Decomposition interview locks Astro+Solid, SvelteKit, or Next.
- **Server:** Bun runtime, TypeScript (per CHOICES G-0008). Binds tailscale0 only, hard-fails on missing interface.

### Ledger schema deltas (S1)
Additive columns to `issues`:
- `priority INT NOT NULL DEFAULT 0` — sort key for ready queue
- `paused INT NOT NULL DEFAULT 0` — boolean; paused rows hidden from DAG, skipped by waiter
- `deferred_at INT` — unix ts of last defer; presence indicates deferred state
- `artifact_dir TEXT` — filesystem path to per-row artifacts (charts, screenshots, prototypes, drafts)
- `draft_md TEXT` — interviewer-cached draft for chat_in rows in current top-3

`parent_id` already exists per slice-tavern request; no change required.

Migration adds columns with backfill defaults. No data loss path.

### Deep modules (all 6 tested)

**1. `ledger-projection` (pure)**
Takes raw `issues` + `issue_events`, returns `{ hitl: Thread[]; afk: DAG }`. Encapsulates: top-3 selection for HITL, DAG window scoping (last-10 completed + in-flight + pending), artifact_dir resolution, draft attachment. Consumed by SSE server, UI components, and tests.

**2. `dag-layout` (pure)**
Takes DAG nodes/edges, returns positioned coordinates. Layered Sugiyama with in-flight center, completed left, pending right. Cache keyed by topology hash; invalidate only on add/remove/state-transition events.

**3. `draft-policy` (pure)**
Takes ledger state + current top-3, returns `{ regenerate: ChatInRow[]; keep: ChatInRow[] }`. Rules: rank change triggers regen of displaced rows; on-focus generation for top-2/top-3 when missing; cached draft considered fresh until rank shuffles.

**4. `ledger-sse-source` (adapter)**
Tails ledger.db via 1s poll (or sqlite update hook if feasible), emits typed deltas. One stream per panel. Supports `Last-Event-ID` resume.

**5. `tailscale-bind` (adapter)**
Resolves tailscale0 IP at boot. Returns bind address or throws. No fallback to 0.0.0.0 ever.

**6. `priority-queue` (pure)**
Applies pause/defer rules to ready set. `paused=1` hidden. Deferred rows scored at `priority - 100`. Returns ordered ready queue. Consumed by waiter and AFK panel.

### Sync contract
- SSE endpoints: `/sse/hitl` and `/sse/afk`.
- Event shape: `{ type: 'row-added' | 'row-updated' | 'row-removed'; row: IssueRow }`.
- Client reconnects with `Last-Event-ID`; server replays from event log seq.

### Pause / defer semantics
- **Pause:** `paused=1`. Row hidden from DAG. Waiter `wait-for-ledger.ts` excludes paused rows from claimable scan. Pause does NOT cascade to children (children stay blocked on the paused parent, naturally).
- **Defer:** `deferred_at=now()`, `priority -= 100`. Row stays visible in DAG marked as deferred. Waiter sees it as lower priority. If new tasks arrive at `priority=0`, deferred-at -100 sits below them; as more arrive, eventually deferred row resurfaces if no normal-priority work remains.

### Pre-draft policy
- Interviewer agent loops: on each tick, identify top-3 chat_in / encounter_reply rows by priority. For each row missing `draft_md` (or with stale draft after rank change), generate draft + 2–3 alternatives. Write to `draft_md` and `artifact_dir/alternatives.json`.
- On user submitting a reply: write `chat_out` row, mark source row resolved, interviewer drafts top-4 (which becomes new top-3) on next tick.

### Artifact storage
- Per-row `artifact_dir`: `~/vault/arc-webui/artifacts/<row-id>/`.
- Contents: free-form files (PNG, MP4, MD, HTML, JSON). UI renders by extension.
- Galleries with >10 files lazy-load thumbnails first, full content on tap.

### Auth
- Tailscale ACL is the only auth. No path tokens, no basic auth, no JWT.
- Server checks `ip addr show tailscale0` at boot. Missing → exit 1 with clear error.

## Testing Decisions

### Good test definition
External behavior only — no implementation details. A test should survive a refactor that preserves the user-observable contract. Inputs are fixture rows; outputs are panel projections, layout coordinates, queue order, or SSE event sequences.

### Tests per module

**`ledger-projection.test.ts`**
- Fixture: 30 mixed rows (various kinds, states, roles, parent_ids).
- Assert: HITL projection returns exactly top-3 chat_in by priority. AFK projection windows correctly (last-10 completed, all in-flight, all pending). Paused rows excluded.

**`dag-layout.test.ts`**
- Snapshot tests: canned DAG → expected node positions.
- Cache test: same topology hash → identical layout; add a row → cache miss → recompute.

**`draft-policy.test.ts`**
- Rank shuffle scenarios: new chat_in arrives at priority=10, displaces top-3 incumbent → assert regenerate set contains displaced row.
- Staleness: row's draft predates last rank change → assert in regenerate.

**`ledger-sse-source.test.ts`**
- Integration with real sqlite: mutate fixture db, assert SSE events emitted in order.
- Reconnect: replay from `Last-Event-ID` returns events seq > id.

**`tailscale-bind.test.ts`**
- Mock `ip addr` output: present → returns IP. Absent → throws with specific error.

**`priority-queue.test.ts`**
- Defer-then-rejoin: defer row at priority=0, add three rows at priority=0 → assert deferred row sits last; add no new rows → assert deferred row eventually surfaces when others claimed.
- Pause: paused row never returned in queue.
- Pause does not affect blocked children (they stay blocked on parent state, not paused state).

### Prior art
- `bin/launch.test.ts` — buildScript snapshot pattern (pure function in/out).
- `bin/ledger.test.ts` — fixture-driven sqlite mutation tests.
- `bin/wait-for-ledger.test.ts` — adapter test with synthetic db.

These three are the model: pure functions get fixture-driven assertions, adapters get real-sqlite integration with controlled state.

## Out of Scope

- **Sound and animations** — nice-to-have, cut from v1 if schedule slips.
- **Multi-user auth** — single user only. Tailscale ACL is the entire auth model.
- **Public deployment** — never. Tailscale-only.
- **Editing the DAG from the UI** — DAG is read-only navigation; mutations only through pause/defer buttons or thread chat.
- **Replacing the ledger schema or message bus model** — `issues` + `issue_events` stays canon per CHOICES G-0001.
- **Replacing tmux launcher** — `bin/launch.ts` and the 4-pane arc session remain unchanged.
- **Adding new agent roles** — three roles (Director, Developer, Admin) per CHOICES A-0002 unchanged.
- **Cloud sync, exports, or third-party integrations** — local-only.
- **Backwards compatibility with old webui URLs** — direct trash + remove, no redirects.

## Further Notes

### Crit path to MVP
S0 (interview) → S1 (schema) → S2 (SSE) → S4 (sketch+design) → S5 (HITL) + S6 (AFK) → S7 (pause/defer) → S8 (pre-drafter loop) → ship. S3 (reference dossier) parallels S1/S2. S9 (trash old) and S10 (auth verification) post-ship after 7-day soak.

### Decomposition interview (S0)
First action after PRD merge: interviewer pane runs a 30-minute decomposition session with the user. Output: stack pick, exact slice sizing, dep order, MVP cut line. Slice plan in `SLICE-PLAN-arc-webui.md` is the starting draft, not the final.

### Reference dossier (S3)
Interviewer assembles 10 reference images (6 game tech trees: Civ, Factorio, Path of Exile, Stellaris, FTL, Slay the Spire; 4 productivity tools: Linear graph view, Height, Notion timeline, Excalidraw). User narrows to 2–3 visual targets before any UI code is written.

### Risk register
- **DAG readability on mobile:** 50 nodes + zoom + 44pt tap targets fight each other on 375px. S4 paper sketch is the gate; if unresolved, narrow window further (last-5 completed instead of last-10).
- **Pre-draft cost:** Opus drafts of top-3 every rank shuffle could be expensive. Mitigated by caching on `draft_md` and only regenerating displaced rows.
- **SSE on mobile cellular:** Battery and reconnect behavior must be tested on real device, not localhost. Acceptance criterion: ≤5% battery/hour with one panel open in foreground.
- **Layout instability:** Topology-change cache invalidation must not jitter the view on minor state transitions. Cache key must be `(node_ids, edge_set)`, not row-content hash.
